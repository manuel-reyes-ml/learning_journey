Portfolio

Four flagships and two supporting projects, ordered by the roles I'm targeting. AI is powered where the model does the core job and assisted where a deterministic core must make the decision.

  • DataVault

    AI-assisted 1099 data platform S1 live, S2 in build

    Flagship for analytics and data engineering

    The live reconciliation pipeline, hardened into a governed data platform: dbt-tested models with a declared grain, data contracts, Airflow, a Docker/ECS deploy, monitoring and a semantic layer. An LLM explains exceptions and, in Stage 3, proposes corrections; a human approves every write.

    • Production live in a regulated operation; success rate held against a freshness SLA
    • Cost 95% less weekly effort; relative figures only
    • Architecture ERISA-driven ADRs, C4 context and container views, dbt tests and contracts

    Python, SQL, dbt, Polars, Airflow, Snowflake, Great Expectations, Docker, AWS ECS, Terraform

  • PostCheck

    AI-powered QA review agent Designed

    Flagship for data engineering and applied AI

    Reviews posted retirement-plan distributions against the request packet and a versioned SOP. Each packet is claimed exactly once, the posted export is parsed deterministically, and a multimodal model reads the scanned forms; rules run first and the LLM handles only what's left. Every verdict lands in an append-only event log that feeds a dbt quality mart.

    • Production read-only by a tested invariant; a verdict is a recommendation, never an authorization
    • Cost one eval suite run on Anthropic, Azure OpenAI and local Ollama
    • Architecture declared grain (one row per packet per review run), ADRs, C4

    Measured against a prompt-only reviewer already in use. The blocking gate is the false-NIGO rate, not accuracy.

    Python, Anthropic SDK, Azure OpenAI, Ollama, Pydantic, dbt, DeepEval, FastMCP, Docker

  • PolicyPulse

    AI-powered policy assistant In build

    Flagship for applied AI

    Answers policy questions with cited sources and escalates when it isn't sure. It starts as RAG over ChromaDB and grows into GraphRAG with Neo4j, with access control enforced at retrieval time.

    • Production RAGAS and DeepEval gates are merge conditions; exposes a FastMCP server
    • Cost cost per query and p95 latency across local and cloud models
    • Architecture retrieval ADRs with rejected alternatives; C4 context and container

    Python, Anthropic SDK, ChromaDB, Neo4j, FastMCP, RAGAS, DeepEval, Streamlit, Docker

  • Crucible

    AI-assisted trading research In build

    Flagship for applied AI and execution safety

    Takes a trading strategy from backtest to paper to live. An LLM analyst reads aggregated backtest results and proposes hypotheses; a deterministic core owns every order, and the live path requires human sign-off and has a kill switch.

    • Production sealed out-of-sample vault, walk-forward validation, intended-vs-filled reconciliation
    • Cost compute per backtest sweep and data-feed cost
    • Architecture execution and risk ADRs, C4, a shared point-in-time primitives library

    Research project. Not investment advice, and no claim of positive returns.

    Python, NautilusTrader, DuckDB, Parquet, Optuna, Ollama, LangGraph, Alpaca, DeepEval

  • AFC

    AI-powered predictive trigger analysis In build

    Supporting project, small-cap research

    An LLM reads SEC filings under a faithfulness gate (≥ 0.9), and an ML model on a point-in-time event study predicts which trigger events follow through, reported as calibrated lift with false-discovery control, never as returns.

  • FormSense
